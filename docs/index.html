01 — team

Your agent
can ask theirs.

Friends on one project, each on their own computer. Agents ask each other's agents, hand work across, and nothing lands on your machine without your yes. It all travels over qh-link, an encrypted direct line between your machines; the project's GitHub repo is just where you find each other.

03 — sessions

Four lines,
one operator.

Open sessions like lines on a board, give each a job, and let them talk: one asks and waits, one hands off and moves on, one spawns a worker that reports back.

Jobs that report backWhoever hands work over hears when it's done, and reports never trigger replies, so nothing ping-pongs.
A model per lineLocal models take turns on your GPU; cloud ones run at the same time.
No collisionsA file one session is editing is locked for the others until it's done.
01 main → 02 testsWhich test in test_cart.py is failing?
02 tests → 01 maintest_total() fails on assert total([10, 20], 0.1) == 33.0.
01 mainedits cart.py, then the tests pass.

04 — safety

The operator's
rules.

Every command runs in your system's own sandbox, so auto mode is safe to leave on. Anything that crosses a line still asks you.

Sandboxed commandsThey write only in the project, can't read secrets, and reach the network through an allowlist, on Linux, macOS and Windows.
Dangerous still asksEven in auto: rm, sudo, git push, curl | sh.
Secrets stay yours~/.ssh, .env and keys are never read without your yes.
Everything undoes/undo reverts the last change; /diff shows the whole session.
