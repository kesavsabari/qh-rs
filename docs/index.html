03 Sessions

Four lines,one operator.

  • CtrlNnew line
  • CtrlG2×2 grid
  • ShiftTabask, auto, plan
01main1
02tests2
03docs3
04web4
  1. main to testsWhich test in test_cart.py is failing?
  2. tests to maintest_total() fails on assert total([10, 20], 0.1) == 33.0
  3. mainedits cart.py, then the tests pass.

Give each line a job and let them talk: one asks and waits, one hands off and moves on, one starts a worker that reports back.

01

Jobs that report back

Whoever hands work over hears when it's done, and reports never trigger replies, so nothing ping-pongs.

02

A model per line

Local models take turns on your GPU. Cloud ones run at the same time.

03

No collisions

A file one session is editing is locked for the others until it's done.

04 Safety

Nothing runswithout your yes.

Every command runs in your system's own sandbox,
so auto mode is safe to leave on.

The operator's rules. Anything that crosses a line still asks you.

01

Sandboxed commands

They write only in the project, can't read secrets, and reach the network through an allowlist. On Linux, macOS and Windows.

02

Dangerous still asks

Even in auto: rm, sudo, git push, curl | sh.

03

Secrets stay yours

~/.ssh, .env and keys are never read without your yes.

04

Everything undoes

/undo reverts the last change. /diff shows the whole session.
